Biologists annotate genomes by searching their proteins against reference databases such as Pfam, which publish a new release every few weeks to months. Each release forces a full re-search, although most of the database has not changed: 86.6% of Pfam's entries matched between releases 38.1 and 38.2 after excluding build metadata and comments. Reusing the old results is hard, because the search programs are fixed binaries whose printed statistics depend on the size of the whole database. We present TARE (Tool Annotation Reuse, Exact), a wrapper that reruns an unmodified program only on the entries that can matter, with the program's own database-size setting pinned to the new release, so that the program itself prints the numbers a full run would print. TARE then tests the replay by adding back entries it left out, and refuses, returning an ordinary full run, if any line changes. Under the contract, every output line except comment headers is byte-identical to a full rerun; the contract assumptions are tested on each update, not proved. In the all-record timing reported here, TARE also reruns the program in full on 299 sampled records drawn from all query records, so a hidden dependency that affects at least 1% of that population ships with probability at most 5%, assuming a valid audit oracle. On Pfam 38.1->38.2, TARE is 3.47x faster than a full rerun under that all-record bounded audit (median over 8 genomes after excluding 1 wall-quality flagged genome; 95% CI 3.30-3.81). Cost of checking versus unchecked replay is 1.58x (C/B over the same unflagged set). Across 715,704 output lines from HMMER and Infernal, not one differed from a full run. TARE refused DIAMOND, whose first filter reads bytes of the neighboring database entry, and BLAST+, whose unpinned probe rows fit none of TARE's column rules.
